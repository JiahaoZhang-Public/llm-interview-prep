# P011 BPE Tokenizer 题解

## 核心思路

1. **初始化**：把语料中每个单词拆成字符序列 + 结束符 `</w>`，统计频率
2. **训练（贪心合并）**：反复统计所有相邻 pair 的出现频次，合并最高频的那对，加入 vocab，直到达到目标 vocab_size
3. **编码**：对新文本，按 merges 的顺序依次尝试合并字符，再查 vocab 表得到 token id
4. **解码**：token id → token 字符串，拼接后去掉 `</w>` 还原空格

## 面试口述模板

> "BPE 的核心是一个自底向上的贪心合并算法。
> 训练时先把每个单词拆成字符加结束符，然后反复找出语料中最高频的相邻 pair 进行合并，
> 每次合并产生一个新 token 加入词表，直到词表大小达标。
> 编码时对输入文本按合并规则依次合并字符对。
> 解码就是查反向映射表把 id 转回字符串。
> 这个算法的优点是能自适应地处理未见过的词（通过回退到字符级别），
> 同时高频词会被合并成完整 token，兼顾了 OOV 问题和效率。"

## 常见坑

- **合并顺序依赖**：encode 时必须按 train 时的合并顺序重放，否则分词结果不一致
- **结束符 `</w>` 处理**：忘加会导致词边界丢失，decode 出来没有空格
- **统计 pair 频次时忘乘词频**：语料中重复出现的词要按词频加权，不能只数一次
- **vocab_size 包含基础字符**：初始字符集已占用一部分 id，实际可合并次数 = vocab_size - 初始字符数

## 复杂度

- 训练：O(V × N × L)，V = 目标 vocab_size，N = 词表条目数，L = 平均词长
- 编码：O(M × L²)，M = merges 数量，L = 单词长度
- 实际工程中用 priority queue 或 trie 加速
