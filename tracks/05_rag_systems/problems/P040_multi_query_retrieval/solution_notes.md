# P040 Multi-Query Retrieval 题解

## 核心思路

1. 对原始 query 生成多个变体（改写、同义替换、不同角度提问）
2. 对每个 query 变体分别执行向量检索，得到多组候选文档
3. 合并所有候选并去重（按 doc_id 去重）
4. 可选：对去重后的结果做 fusion scoring（如 Reciprocal Rank Fusion）再排序
5. 返回最终 top-k 文档

## 面试口述模板

> "Multi-Query Retrieval 解决的是单一 query 表达不充分的问题。我先用 LLM 或规则生成原始 query 的 3-5 个变体，从不同角度描述同一需求。然后对每个变体独立检索，把所有结果合并去重。去重时用 doc_id 做 key，如果同一文档被多个变体检索到，说明它很可能高度相关。最后可以用 RRF 公式对多次排名做融合：RRF_score = Σ 1/(k + rank_i)，得到最终排序。"

## 常见坑

- **query 变体质量**：垃圾变体会引入噪声，需要控制生成质量和数量
- **去重逻辑**：按 doc_id 去重，保留最高分数或融合分数，不要保留重复文档
- **RRF 中的 k 值**：通常取 60，是经验超参，面试时要知道它的作用是平滑排名差异
- **延迟翻倍**：多个 query 检索可以并行执行，串行会导致延迟线性增长

## 复杂度

- 时间：O(m · n · d) 检索 + O(m · n · log n) 排序，m 为 query 变体数
- 空间：O(m · n) 存储所有候选，去重后 O(n)
