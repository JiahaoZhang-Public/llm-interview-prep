# P044 Memory System 题解

## 核心思路

1. 用滑动窗口维护 agent 的短期记忆，限制上下文长度在 token budget 内
2. 数据结构：一个 deque 或 list 存储 message 记录，新消息从尾部追加
3. 当总 token 数超过窗口大小时，从头部移除最旧的消息
4. 保留 system prompt 不被裁剪（固定在窗口之外单独计算）
5. 可选：被移除的消息做摘要压缩，保留关键信息

## 面试口述模板

> "短期记忆的核心是滑动窗口。我维护一个消息列表和一个 token 计数器。每次添加新消息时累加其 token 数，如果总量超过预设上限，就从列表头部逐条移除旧消息并减去对应 token 数，直到总量回到阈值以下。System prompt 是特殊的——它永远保留不被移除，token 预算单独为它预留。进阶做法是对被移除的消息先做摘要，把摘要作为一条特殊消息保留在窗口中。"

## 常见坑

- **token 计算方式**：要用和 LLM 一致的 tokenizer，不能简单按字符数估算
- **system prompt 被裁**：system prompt 必须固定保留，不参与滑动窗口淘汰
- **tool 消息成对性**：tool_call 和 tool_result 应该成对保留或成对移除，否则上下文不一致
- **边界条件**：单条消息超过整个窗口大小时需要截断该消息或报错

## 复杂度

- 时间：add O(1) 均摊（偶尔触发淘汰 O(k)，k 为移除条数）
- 空间：O(W)，W 为窗口大小（token 数）
