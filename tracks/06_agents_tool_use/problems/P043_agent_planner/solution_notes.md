# P043 Agent Planner 题解

## 核心思路

1. 给定用户任务和可用工具列表，生成一个有序的执行计划（step 列表）
2. 每个 step 包含：tool_name、参数来源（常量或前序 step 的输出）、依赖关系
3. 实现方式：用 LLM 生成计划 JSON，或用规则/模板匹配分解任务
4. 计划需满足 DAG 约束：step 只能依赖编号更小的 step
5. 执行时按拓扑序依次执行，前序 step 的输出作为后续 step 的输入

## 面试口述模板

> "Agent Planner 把复杂任务分解为多个工具调用步骤。我会让 LLM 输出结构化计划，每个 step 包含要调用的工具、参数和依赖。关键约束是步骤间形成 DAG——每步只能引用之前步骤的输出。实现上我会校验计划的合法性：工具名必须在可用列表中、依赖的 step 编号必须小于当前编号、必填参数必须有来源。执行时按顺序跑，把每步结果存入上下文供后续步骤引用。"

## 常见坑

- **循环依赖**：计划中不能有环，需要校验 DAG 合法性
- **工具幻觉**：LLM 可能计划使用不存在的工具，需校验 tool_name
- **参数传递**：前序 step 输出的格式可能和后续 step 期望的输入不匹配，需类型检查
- **计划过长**：设置最大步骤数限制，避免生成冗余计划

## 复杂度

- 时间：O(S · C_tool)，S 为步骤数，C_tool 为单步工具执行开销
- 空间：O(S) 存储计划和中间结果
